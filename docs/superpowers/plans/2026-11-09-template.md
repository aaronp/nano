# The component template — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `templates/nano-template`, a stand-alone package of components (a Timer) built against the published `@pritzlaff/nano-*`, whose build is a module + manifest a host can import from a URL; plus checks and export from this repo.

**Architecture:** The folder is outside the workspace with its own lockfile. `src/` holds the rune component, its element, and the entry (`catalog`, `define()`); `scripts/build.ts` bundles the entry with the shared packages external and writes `manifest.json` (from `src/manifest.ts`, a pure function of the catalog) and the preview page. This repo gains `make template-check` (the template against the libraries in the commit) and the export.

**Tech Stack:** Bun, TypeScript, TypeBox, Lit 3, happy-dom, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-09-template-design.md`

## Global Constraints

- The template imports only `@pritzlaff/nano-core`, `@pritzlaff/nano-runes`, `@pritzlaff/nano-elements` (`^0.1.0`), `typebox` (`^1.4.0`) and `lit` (`^3.0.0`) — never this repo's sources.
- Component id `nano.template/timer`, tag `nano-timer`, kind `timer`, title `Timer`.
- Manifest version `1`; `module` is `./index.js`, relative to the manifest.
- Every file at most ~200 lines; every export has a 1–2 line purpose comment.
- Network installs: `BUN_TMPDIR=$TMPDIR BUN_INSTALL_CACHE_DIR=$TMPDIR/bun-cache` and the allowed domain `registry.npmjs.org`.
- Never commit `kerits/`, `puzzles/`, `wires/`, `debounce/`. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Starting twice doesn't double the ticks**, and `setInterval` while running restarts one clock (Task 1).
2. **A removed Timer stops ticking** or at least never throws: there is no unmount hook in runes, so the timer must not leave a live interval publishing into a dead environment (Task 1 — test it; if runes can't tell, record a ruling with a `ponytail:` comment).
3. **`setInterval` below 10, or not a number, is refused** through the schema, not silently clamped (Task 1).
4. **The built module has no copy of the shared packages** (no `lit` or `typebox` code inlined; subpaths like `typebox/value` stay bare too) (Task 3).
5. **The export never force-pushes and is a no-op when nothing changed** (Task 5).
