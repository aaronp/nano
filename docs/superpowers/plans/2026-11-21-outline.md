# The Outline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Rename the Platform to the Outline and make pages a tree (stable ids, shared order), shown by both hosts.
**Spec:** `docs/superpowers/specs/2026-11-21-outline-design.md` (all of it, including the settled and decided sections); ADR-0040, ADR-0039.

## Global Constraints
- `Outline = { roots: PageId[]; pages: Record<PageId, Page> }`; `Page = { title?; children?: PageId[]; slots; layout?; meta? }`; `apply` refuses missing ids, a page in two places, cycles, orphans (`invalid-input`, naming the page); `Outline.parse` reads a flat `{ pages }` as every page a root, in document order.
- Change report `{ added, removed, changed, moved, resolved }`; a parent whose only change is `children` is not `changed`; a roots-only change is reported and bumps the version.
- `HostOutline { document, apply, changed (event) }`, namespace `nano.outline`; the host pod `outline` publishes the library's changes; HOST_PODS = ui, deploy, outline.
- Names: `@pritzlaff/nano-outline` (folder `packages/outline`), `Outline.create`, `Outline.parse`, `HostOutline` (schemas keep `DocAt`, `ApplyAt`), bundle `{ app, outline }` (still reads `{ app, platform }` and plain nano.json), storage key `nano-workspace.outline` (old key read when absent, removed by the workspace after a good save).
- Workspace rules (Main first root, not removable, may have children; reserved ids at `/p/<id>`) stay the workspace's.
- No file over 150 lines (workspace-dock.ts ≤226); the nav's tree code splits into its own modules (agreed); internal helpers are fine (user guidance); public shapes are only those above.
- Tests: `bun test --isolate` in packages/outline, nano, ui, ui-workspace, host-react, examples; `bunx tsc --noEmit`.

## Review Focus
1. Moving a page (drag, keyboard, or a pod's apply) keeps its id, route and slots; both hosts show the new place after a reload.
2. Old data: a flat stored document, an old `{ app, platform }` file and the old storage key all load into the same tree, losing nothing.
3. Removing a page with children asks, removes the subtree, leaves pods alone and routes away from removed pages.
4. An import into a tree: suffixed ids renamed in its lists, roots appended, Main's children kept.
5. Keyboard nesting (Alt+→/←, Alt+↑/↓) works and is announced.
