# Desk View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `<c-desk>`, a mixing-desk systems view: runtimes as boxes holding pod columns, with jacks and cords. It has
snap, push-apart, Align and Compact, saves its arrangement in `layout.desk`, and edits pipes behind an edit toggle.
The work also adds core's exported `lookup` and the `pipe`/`unpipe` edits, and deletes Connections' puzzle mode.

**Architecture:**
- **Core first:** `lookup(d)` is exported, and `AppDeployment.edit` gains `pipe`/`unpipe`.
- **Shared edits:** Connections' connect and disconnect are rebuilt on those edits, as host-level functions.
- **The Desk** is three pure modules (what to show, arrangement, cords) and a small Lit element over them:
  - It reuses `snapshotOf`, `buildModel`, `viewOf`, `checkConnect` and `jacksOfImpl` from `wires/`.
  - It reuses `opCord`'s colours.
  - It adds no second model.

**Tech Stack:** TypeScript, Lit, bun test (`--isolate`), happy-dom, nano-core.

**Spec:** `docs/superpowers/specs/2026-11-18-desk-view-design.md`. The spike is `docs/spikes/desk-spike.html`; its
layout rules for B and C and its push algorithm are the reference.

## Review Focus

1. **After an apply removes a pod or runtime:** stale positions are pruned, and a new pod gets a free slot that
   overlaps nothing (Task 5).
2. **A pod placed in two runtimes** gets a column in each. A pipe is drawn only in its own runtime (Task 4).
3. **With edit off,** Delete, jack clicks and cord clicks apply nothing (Task 7).
4. **A non-fitting, same-pod or duplicate connection** is refused with `checkConnect`'s message, and nothing is
   applied (Task 7).
5. **A file with no `layout.desk`, or a malformed one,** gets the automatic layout and doesn't throw (Task 5).

### Task 4: Desk model: what the Desk shows (pure)

**Files:**
- Create: `packages/ui-workspace/src/desk/model.ts`.
- Test: `packages/ui-workspace/test/desk/model.test.ts`.

**Interfaces:**
- Consumes: `snapshotOf`, `buildModel` (with `panels: []`, so every pod is in the rack and `P` holds every jack),
  `viewOf`/`ViewSettings`, `lookup`, and `OpPair` from `wires/calls.ts`.
- Produces:
  ```ts
  export type Column = { runtime: string; pod: string; implementation: string; ins: string[]; outs: string[] }   // jack keys (`pod port:dir`), in op order
  export type DeskModel = { runtimes: { id: string; columns: Column[] }[]; pipes: Wire[]; calls: { id: string; runtime: string; pairs: OpPair[]; jacks: string[] }[]; rank: Record<string, number>; wires: Model }
  export function deskModel(d: AppDeployment, registry: Registry, opCalls: OpPair[], view: ViewSettings, application: string): DeskModel
  export function rankOf(d: AppDeployment): Record<string, number>
  ```
  - `wires` is the unfiltered `buildModel` result. It is what `checkConnect` runs against.
  - `ins` and `outs` hold only the jacks left by `viewOf(wires, view)`.
  - A runtime with no columns left is dropped.
  - The application pod (`ui`) never shows.
- **`rankOf`** is the longest path over runtime links. An edge in runtime R from caller c gives X → R for every X in
  `lookup(d).placedIn.get(c)` with X ≠ R. Only call edges count. Use memoised DFS, and treat a cycle as 0 at the
  re-entry, as the spike's `depth` does.

### Task 5: Desk arrangement: placement, snap, push, fit, align, compact, persistence (pure)

**Files:**
- Create: `packages/ui-workspace/src/desk/arrange.ts`.
- Test: `packages/ui-workspace/test/desk/arrange.test.ts`.

**Interfaces:**
- Consumes: `DeskModel`.
- Produces:
  ```ts
  export type XY = { x: number; y: number }
  export type DeskLayout = { snap: boolean; compact: boolean; runtimes: Record<string, XY>; pods: Record<string, Record<string, XY>> }  // pods: runtime → pod → position inside the runtime box
  export type Sized = XY & { w: number; h: number }
  export const GRID = 20
  export function readLayout(raw: unknown): DeskLayout          // malformed or missing → { snap: true, compact: false, runtimes: {}, pods: {} }
  export function columnSize(c: Column, compact: boolean): { w: number; h: number }   // w ≥ 190 (150 compact) and fits its longest in label + out label; h from jack rows (26 / 20)
  export function arrange(m: DeskModel, l: DeskLayout): { layout: DeskLayout; runtimes: Record<string, Sized>; columns: Record<string, Record<string, Sized>> }
  export function push(boxes: Record<string, Sized>, placed: string, snap: boolean): Record<string, XY>   // new positions of the boxes it moved
  export function align(m: DeskModel, l: DeskLayout): DeskLayout   // runtimes and pods cleared, so arrange lays them out again; snap and compact kept
  export function setSnap(l: DeskLayout, on: boolean): DeskLayout  // on: every position rounded to GRID; off: positions unchanged
  ```
  - `arrange` keeps saved positions, prunes runtimes and pods the model doesn't have, and places the rest:
    - **Columns** go left to right inside their runtime, after the rightmost saved one.
    - **Runtimes** follow B: grid column = `rank`, column x = previous column's x plus its widest runtime plus 60,
      stacked down with 24 between them.
    - Then each runtime is fitted to hold its columns: furthest column edge plus 20 padding, rounded up to `GRID`
      when snap is on. The minimum width is 160.
  - Column y inside a runtime starts at 40, the header. Columns are clamped to x ≥ 20 and y ≥ 40, and runtimes to
    ≥ 0.
  - The push algorithm is the spike's `push`. It moves only +x or +y, whichever is shorter, cascades through a
    queue, and never moves the placed box or tests a box against itself. Margin = `GRID`.

- [ ] **Step 1: Write the failing tests:**
  - `readLayout of junk is the default`: `readLayout(undefined)`, `readLayout(42)` and `readLayout({ snap: 'x' })` each equal the default.
  - `B places callers left`: on the room/backend model, `runtimes.backend.x > runtimes.room.x + runtimes.room.w`.
  - `runtimes in one rank stack`: two rank-0 runtimes have the same x and don't overlap.
  - `a runtime holds its columns`: for every column, `x + w ≤ runtime.w` and `y + h ≤ runtime.h`.
  - `saved positions are kept and stale ones pruned`: save `pods.main.r = { x: 400, y: 40 }` and a `pods.main.gone`. After `arrange`, r is at 400 and `gone` is absent.
  - `a new pod doesn't overlap saved ones`: add a pod to the model with the others saved. No two columns overlap.
  - `push moves an overlapped box right or down and cascades`: three boxes in a row, drop the first onto the second. No pair overlaps, and the placed box is unchanged.
  - `push terminates on a self-overlapping set`: boxes that all overlap finish, with no pair overlapping.
  - `setSnap on rounds, off keeps`: positions `{ x: 33, y: 47 }` become `{ x: 40, y: 40 }` with snap on, and stay `{ x: 33, y: 47 }` with snap off.
  - `align clears positions, keeps settings`.
  - `compact columns are narrower`: `columnSize(c, true).w < columnSize(c, false).w` for a short-label column.
