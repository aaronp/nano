# Wrappers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wrap a live instance so everything routed to it goes through a wrapper (forward, broadcast, race, buffer, map), with `Registry.replace`, `HasRuntime`, and views hiding by owner instead of by id.

**Architecture:** `Registry.replace` swaps what sits at an id keeping its subscriptions and emits `instance-replaced`; the runtime moves environment handles on that delta. `core/src/wrap.ts` builds a wrapper component that offers X's ops, owns an inner registry+runtime holding X under the same id, routes each call through a strategy, republishes the parts' publishes from X, and forwards parts' outward calls to the outer runtime via a Policy. Platform and wires views hide entries owned by a `view`.

**Tech Stack:** TypeScript, Bun test, TypeBox, lit (views).

**Spec:** `docs/superpowers/specs/2026-11-10-wrappers-design.md`

## Global Constraints

## Review Focus

1. Closing the widget whose instance was wrapped (a `PlacedElement` disconnect) must still remove what sits at its id — today it only removes `mine.inst`, which the wrapper replaced (Task 4 test).
2. A publish by the part during a wrapped call must reach X's subscribers exactly once (Task 2 test).
3. Wrapping an already-wrapped instance, then unwrapping twice, restores the original with its subscriptions (Task 3 test).
4. A `ModelElement` view on X keeps updating across wrap and unwrap (Task 4 test).
5. A delivery to a paused `buffer` wrapper must not stop a runes component's state updates (runes doesn't await publishes) (Task 3 test).

### Task 2: `HasRuntime`, `wrap` / `unwrap` with `forward`

**Files:**
- Create: `packages/core/src/wrap.ts`
- Modify: `packages/core/src/index.ts` (`export * from './wrap'`)
- Test: `packages/core/test/wrap.test.ts`

**Interfaces:**
- Consumes: `Registry.replace` (Task 1).
- Produces:
  - `type HasRuntime = { runtime: Runtime }`; `hasRuntime(v: unknown): v is HasRuntime` (true when `v.runtime` has `call`, `notify`, `listen` functions and a `registry`).
  - `type Call = (part: string, op: string, arg: unknown) => Promise<Result>`
  - `type Strategy = ((op: string, arg: unknown, parts: string[], call: Call) => Promise<Result>) & { pause?(): void; resume?(): Promise<void> }`
  - `Strategies.forward: Strategy`
  - `wrap(outer: Runtime, id: string, strategy: Strategy, opts?: { map?: Record<string, { part: string; op: string }>; owner?: Owner }): Result<HasRuntime>` — returns the wrapper's value.
  - `unwrap(outer: Runtime, id: string): Result<void>`
  - `WrapperOps = { pause, resume, parts }` — `composable/wrapper/pause` (input ignored, void), `…/resume` (same), `…/parts` (`Null → string[]`), each described.

- [ ] **Step 1: Failing tests** (`wrap.test.ts`; reuse the counter/logger shapes from `runtime.test.ts`)
  - `test('a wrapped instance still answers calls and its subscribers still hear it, once')` — counter `c` → `log`; `wrap(rt, 'c', Strategies.forward)`; call `Inc` on `c` → value 1; log received `[1]` exactly once.
  - `test('a delivery to a wrapped listener reaches the part')` — wrap `log`; publish from `c`; the part's array has the value.
  - `test('every hop is traced on the inner runtime')` — `wrapper.runtime.listen` sees a `call` trace for `Inc` with target `c`.
  - `test("a part's call to an outer neighbour and to registry reaches the outer runtime")` — a part that calls `log` and `registry` snapshot via its env; results ok; snapshot id is the outer registry's.
  - `test('unwrap restores the original; it publishes once, to the outer registry only')` — wrap then unwrap; `get('c')` is the original; its `env.handles()` has exactly one handle, outer coord; Inc logs once.
  - `test('wrap of an unknown id and unwrap of a non-wrapper error')`.
  - `test('hasRuntime tells a wrapper value from a plain one')`.
  - `test('the wrapper keeps the component id and offers the parts op')` — snapshot entry for `c` has `component: 'com.acme/counter'`; `parts` returns `['c']`.
- [ ] **Step 2: Run** `cd packages/core && bun test test/wrap.test.ts` — Expected: FAIL (module not found).
- [ ] **Step 3: Implement** per the spec §3:
  - Inner registry id `${outer.registry.id}/${id}` (unique per wrapped id).
  - Inner runtime Policy: `call(from, t, op, arg)` goes to `outer.call(outerCoord, t, op, arg)` when `t === 'registry'` or `!inner.registry.get(t)`; else the inner call.
  - Wrapper component: `Components.create(x.component.id, …, { description })`; for each of X's actions: with `run` → an action (no `emits`) whose run is `strategy(key', arg, parts, call)` where `key'`/part come from `map` when present; without `run` → a source (no run). Plus the three `WrapperOps`.
  - Republish: `inner.listen(t => t.kind === 'publish' && isOk(t.result) && t.from.registry === innerId && offered(t.op) && wrapperEnv.notify(opOf(t.op), t.data))`.
  - `wrap` order: instantiate, `outer.registry.replace(id, wrapperInst, opts.owner)`, then `inner.registry.add(id, x, { kind: 'wrapper', name: id })`.
  - `unwrap`: error unless `hasRuntime(value)` and `parts` is exactly one; `inner.registry.remove(part)` then `outer.registry.replace(id, part)`.
