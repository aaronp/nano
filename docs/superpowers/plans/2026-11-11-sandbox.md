# Sandboxed Components Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Import packages as trusted or sandboxed, deploy each instance as `host`, `sandbox` or `isolated-sandbox` through an app-level DeployStrategy, guard what an instance may call, label how each was deployed (O(1) to query), and highlight sandboxed instances in the views.

**Architecture:** Core gains registry labels (indexed) and an `outward` selector guard on `wrap`. The app (`ui-workspace/src/sandbox/`) adds a stand-in `Component` that talks to an iframe over a MessagePort, a bootstrap module the iframe runs, a frame layer and `<c-sandboxed>` element, and a DeployStrategy used by the platform's create op and the dock. Imports gain a trust choice; a sandboxed import reads its catalog through an isolated probe iframe. Views read `nano/deploy` labels.

**Tech Stack:** TypeScript, Bun (test + build), TypeBox, lit, happy-dom (tests; it can't run iframes).

**Spec:** `docs/superpowers/specs/2026-11-11-sandbox-design.md`

## Global Constraints

- Branch `sandbox`; one commit per task; messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Every new op typed and described; the `described` guard tests stay green.
- Host code never imports a sandboxed package's module (probe included: it runs in an isolated iframe).
- Everything an iframe sends is data, checked before use.
- Label keys: `nano/deploy` (`host|sandbox|isolated-sandbox`), `nano/trust` (`trusted|sandboxed`), `nano/guarded` (`true`).
- Ready timeout 10 s (a named constant); no per-call timeout.
- Full check: `$TMPDIR/all.sh`; before the final review `make packages`, the ui-workspace build, and `make template-check` (network env vars).

## Review Focus

1. A sandboxed import whose module fails to load (404, CORS, no `catalog`) adds nothing and says why (Task 6 test).
2. Removing a sandboxed instance from its last registry removes its iframe; removing it from one of two keeps it (Task 4 test).
3. Selectors match ids and op keys literally apart from `*` (op keys contain `.`, e.g. `composable.bundle/log/info`) (Task 2 test).
4. Moving a `<c-sandboxed>` (disconnect + reconnect, as the dock does) never moves or reloads its iframe (Task 4 test).
5. Labels stay with an entry across `replace` — so guarding (wrapping) a deployed instance keeps `nano/deploy` (Task 1 + Task 5 tests).
