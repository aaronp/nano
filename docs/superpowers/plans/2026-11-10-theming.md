# Themes and a component library for widgets — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** `--nano-*` tokens and an adr-style class library in `@pritzlaff/nano-elements`; our widgets on it; the four Decision Ledger themes in the workspace, mapped to the contract; a Components gallery with layouts and a compare-themes view.

**Spec:** `docs/superpowers/specs/2026-11-10-theming-design.md`

## Global Constraints
- Tokens (exactly): `bg surface surface-2 border border-strong fg fg-2 muted on-accent accent accent-soft focus good good-bg bad bad-bg warn warn-bg font font-display font-mono radius radius-s s1 s2 s3 s4 s5 s6 s7 s8`, as `--nano-<name>`.
- Widgets' styles contain no colour literal except as a `var(--nano-…, <fallback>)` fallback (a test scans their sources).
- No changes to `packages/core` or `runes`. Files ≤ ~200 lines. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus
1. **A page with no theme looks as before** (fallbacks are the current dark palette).
2. **Every workspace theme, in each of its schemes, yields every `--nano-*` token** (Task 2's test).
3. **Switching theme restyles widgets already on the page** (the root's custom properties change; nothing is re-rendered).
4. **Compare columns are self-contained:** a column's widgets take that column's theme, not the page's.
5. **Bare `button`/`input`/`select` still look right** in elements that don't use the classes.
