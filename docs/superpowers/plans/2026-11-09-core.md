# @composable/core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new package `@composable/core` that lifts plain values and functions into named coordinates which can be called, published from, subscribed to and observed. The core is small, single-purpose pieces.

**Architecture:** Five files, one job each. `data.ts` holds the plain types. `component.ts` wraps "make" and "act" functions, and `env.ts` gives an instance its handles. `registry.ts` stores instances and subscriptions and reports changes. `runtime.ts` invokes by coordinate over one registry, publishes the registry's changes as events, and can be wrapped by policies. The old `@composable/sdk` is untouched.

**Tech Stack:** Bun workspaces, TypeScript (strict), TypeBox 1.x (`typebox`, `typebox/value`), `bun test`.

**Spec:** `docs/superpowers/specs/2026-11-09-core-design.md`

## Global Constraints

- New package `packages/core`, name `@composable/core`, `"type": "module"`, `exports: {".": "./src/index.ts"}`. Its only dependency is `typebox` (`^1.4.0`, the version used in `packages/sdk/package.json`).
- Each `src/*.ts` file holds a few operations in about 50–100 lines and never more than 200. Check with `wc -l packages/core/src/*.ts`.
- Every exported type and function has a 1–2 line comment stating its **purpose and responsibility**, not how it works.
- Nothing from `@composable/sdk` is imported. No handle conveniences (`use`, `within`, `withX`), no error-code enum, no state wrapper, no bindings or dependencies, no loop budget.
- Every task ends green on `cd packages/core && bun test` and `npx tsc -p .` from the repo root.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never commit `kerits/` or `puzzles/`. Don't push.

## Rulings on the spec

- **Instances, not components, carry the action map.** The spec's chained example (`.action().action()`) conflicts with "`action` reports `'added' | 'replaced'`". `Component.action` returns that report, so the examples use one statement per action. `instantiate` copies the component's actions into the instance, so `env.register` can add an op to one instance at runtime (the spec's `env.register(CounterUpdated)`). Adding an action to a component later affects only instances made after that.
- **A source must be declared before it is published.** `notify` looks the op up in the publishing instance's actions, either from the component or through `env.register`. An undeclared op fails with `{ error: 'unknown op …' }`. This is how a subscriber or a validator learns the payload schema.
- **Nested Results.** `Runtime.notify` returns `Result<Result[]>`. The outer Result says whether the publish was allowed: a policy can refuse it, and a payload that fails validation is refused. The inner list holds one Result per delivery. `Handle.notify` returns the same thing, and `Environment.notify` returns one of these per registry, as the spec says.
- **Emit failures** go in the action's success Result as `detail: { emits: Result[] }`. The field appears only when at least one emit failed.
- **Handles go through the policy.** `Runtimes.create(registry, wrap?)`: the handles given to instances call the *wrapped* runtime, so a policy sees every call and notify a component makes. Deliveries to listeners invoke the listener's action directly.
- **`add` takes an in-process `Instance`.** It is not JSON, so `add` is not remote-safe. That is accepted for the core; a remote runtime would add by catalog id later.

## Review Focus

1. An instance removed while a notify is delivering: later deliveries to it must fail as `{ error }` in their own slot and not throw (Task 4).
2. Re-adding an id that already exists in a registry: refused with `{ error }`, and the existing instance is untouched (Task 3).
3. One instance in two registries, removed from one: its handles shrink to the other, and `env.notify` reaches only that one (Task 5).
4. A `'*'` subscriber whose target action throws: the other listeners still get the event (Task 4).
5. `env.notify` before the instance is in any registry returns `[]` and does not throw (Task 2).

- `type Op<I extends TSchema | undefined = TSchema | undefined, O extends TSchema | undefined = TSchema | undefined> = { ns: string; name: string; input?: I; output?: O }`
- `const Ops = { action(ns, name, input, output), source(ns, name, output), sink(ns, name, input), key(op): string }`. `key` returns `` `${ns}/${name}` ``. The constructors keep the schema types generic.

### Task 2: `component.ts` and `env.ts`

**Files:**
- Create: `packages/core/src/component.ts`, `packages/core/src/env.ts`
- Test: `packages/core/test/component.test.ts`

**Interfaces — Consumes:** Task 1. **Produces:**
- `type Run<A, I, O> = (instance: A, arg: I, env: Environment) => O | Promise<O>`
- `type Action<A> = { op: Op; run?: Run<A, any, any>; emits?: Op[] }`. Without `run`, it is a declared source that is published only by `notify`.
- `type Component<A> = { id: { ns: string; name: string }; make(env: Environment): A; actions: Map<string, Action<A>>; action<I, O>(op: Op<I, O>, run?: Run<A, StaticOf<I>, StaticOf<O>>, opts?: { emits?: Op[] }): 'added' | 'replaced' }`. `StaticOf<undefined>` is `undefined` and `StaticOf<T extends TSchema>` is `Static<T>`.
- `type Instance<A = unknown> = { component: Component<A>; value: A; actions: Map<string, Action<A>>; env: Environment }`
- `const Components = { create<A>(id, make): Component<A>, instantiate<A>(c): Instance<A>, invoke(inst, op: string, arg): Promise<Result> }`
  - `invoke` runs the action and turns a throw into `err(message)`. An unknown op, or one with no `run`, gives `err('unknown op <key>')`.
  - On success it then handles emits: for each emitted op it invokes that op's action and calls `env.notify(op, value)`. Failed emits go in `detail.emits`.
- `type Handle = { coord: Coord; notify(op: Op, data: unknown, correlation?: string): Promise<Result<Result[]>>; call(target: string, op: Op, arg: unknown): Promise<Result> }`
- `type Environment`:
  - `handles(): Handle[]`
  - `added(h: Handle, announce: (type: 'op-added' | 'op-removed', op: Op) => void): void`
  - `removed(coord: Coord): void`
  - `notify(op, data, correlation?): Promise<Result<Result[]>[]>`
  - `register(op, run?, opts?): 'added' | 'replaced'`
  - `unregister(op): boolean`
- `const Environments = { create(actions: Map<string, Action<any>>): Environment }`
  - `register` and `unregister` change that map and call each handle's `announce`.
  - `added` ignores a handle whose coord is already present, compared by `registry` and `instance`.

### Task 3: `registry.ts`

**Files:**
- Create: `packages/core/src/registry.ts`
- Test: `packages/core/test/registry.test.ts`

**Interfaces — Consumes:** Tasks 1–2. **Produces:**
- `type Snapshot = { id: string; instances: { id: string; ops: Op[] }[]; subscriptions: Subscription[] }`
- `type Registry`:
  - `id: string`
  - `get(id): Instance | undefined`
  - `add(id, inst): Result<void>`. A duplicate id gives `err`.
  - `remove(id): Result<void>`. An unknown id gives `err`. It also closes every subscription where `listener === id`.
  - `subscribe(s: Omit<Subscription, 'id'>): Result<Subscription>`. The listener must exist, or `err`. The source need not exist. The id is `crypto.randomUUID()`.
  - `unsubscribe(id): Result<void>`
  - `matching(source: string, op: string): Subscription[]`. These are subscriptions whose `source` is `source` or `'*'`, and whose `op` is `op`.
  - `snapshot(): Snapshot`
  - `emit(d: Delta): void`
  - `listen(fn: (d: Delta) => void): () => void`
- `const Registries = { create(id: string): Registry }`
  - Every successful `add`, `remove`, `subscribe` and `unsubscribe` emits its delta. On `remove`, the `subscription-closed` deltas come before `instance-removed`.
  - The registry is data plus listeners only: it never invokes actions.

### Task 4: `runtime.ts`

**Files:**
- Create: `packages/core/src/runtime.ts`
- Test: `packages/core/test/runtime.test.ts`

**Interfaces — Consumes:** Tasks 1–3. **Produces:**
- `type Runtime = { registry: Registry; call(from: Coord, target: string, op: string, arg: unknown): Promise<Result>; notify(e: Event): Promise<Result<Result[]>> }`
- `type Policy = (inner: Runtime) => Runtime`
- `RegistryOps`. Actions, with `ns` `'composable'`:
  - `add` takes `{ id, instance }`;
  - `remove` takes the id;
  - `subscribe` takes `Omit<Subscription,'id'>`;
  - `unsubscribe` takes the id;
  - `snapshot`.

  It also has one source op per `Delta` type, named as the type, for example `'composable/instance-added'`. Schemas can be `Type.Unknown()` wherever an exact schema would cost lines.
- `const Runtimes = { create(registry: Registry, policy?: Policy): Runtime }`. It does this:
  1. **The registry is an instance inside itself.** It adds an instance under the id `'registry'` whose value is the registry, whose actions are `RegistryOps`, and whose delta sources are declared.
  2. **Deltas become events.** It runs `registry.listen(d => notify({ from: { registry: id, instance: 'registry' }, op: 'composable/' + d.type, data: d }))`.
  3. **Handles follow membership.** On `instance-added`, it builds a handle for the instance whose `notify` and `call` go through the *policy-wrapped* runtime. It then calls `inst.env.added(handle, (type, op) => registry.emit({ type, instance, op: Ops.key(op) }))`. On `instance-removed`, it calls `env.removed`.
  4. **`call`** looks up the target, checks `arg` against `op.input` with `Value.Check` when there is a schema, then runs `Components.invoke`.
  5. **`notify`** looks up `e.op` among the publishing instance's actions and checks `data` against its `output`; failing either gives an outer `err`. It then delivers to each `matching` subscription in turn, invoking the listener's `target` action and isolating failures. A listener that is gone gives `err` in its own slot.
  6. It returns `policy ? policy(base) : base`.

  - A call whose arg fails the schema gives `err`.

- **"Lift a plain counter"**
  - `let counter = 0; const increment = () => { counter = counter + 1 }`, wrapped as an object `{ get: () => counter, increment }`.
  - `inc` emits `counter-updated`.
  - A logger component subscribed to it records `[1, 2]` after two calls.
- **"Watch a registry"**
  - A watcher subscribed with `'*'` on `'registry'` records every delta type: instance-added, subscription-opened, op-added, subscription-closed and instance-removed.
  - Its own add comes before its subscription, so it starts recording at its own `subscription-opened`.
- **"Subscribe and unsubscribe at runtime by calling the registry"**
  - Both are done through `handle.call('registry', RegistryOps.subscribe, …)`.
  - After unsubscribe, the logger stops receiving events.
- **"One instance, two registries"**
  - One counter instance is added to registries A and B, each with a logger. `inc` through either reaches both loggers.
  - After removing it from A, only B's logger receives events. This is Review Focus 3.
- **"A policy: components may only subscribe themselves"**
  - The policy `selfOnly` is defined inside the test, in about 10 lines. It refuses a `call` to `'registry'` of `subscribe` or `unsubscribe` where the listener is not `from.instance`. For unsubscribe it finds the listener through `registry.snapshot()`.
  - The test shows one refusal and one success.
- **"Register an op at runtime"**
  - A component calls `env.register(NewSource)` inside `make`, before it has any handles, and again after joining.
  - The watcher sees `op-added` for the second only. The first is already in `instance-added`'s `ops`.
