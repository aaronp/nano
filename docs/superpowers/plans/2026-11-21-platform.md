# The Platform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pages become their own layer. A framework-free `@pritzlaff/nano-platform` owns the UIDeployment and changes it with one `apply`. It resolves slots against the Application and opens pages through `getOrCreate`. The workspace becomes a client of it.

**Architecture:**
- **New package** `packages/platform`, which depends only on nano-core. It holds:
  - the document types, schema, and parse/serialise;
  - the `Target` builder (moved from the workspace);
  - `Platform.create`;
  - the `HostPlatform` interface.
- **The workspace** keeps one Platform instance. It persists the instance under its own storage key, builds every page edit as a `next`, and renders resolved slots.
- **Core** is untouched.

**Tech Stack:** TypeScript, TypeBox, bun test, Lit and golden-layout (workspace only).

**Spec:** `docs/superpowers/specs/2026-11-21-platform-design.md` (ADR-0038; it builds on ADR-0031, 0034, 0035, 0036 and 0037)

## Global Constraints

- **Core is untouched by pages.** Pages live in `packages/platform` and the workspace. No core export changes.
- **The Platform's `apply` runs synchronously and notifies its listeners synchronously.** Its change report is keyed by page (`added`, `removed`, `changed`). It accepts an optional `base` version and refuses when `base` ≠ the current version (`invalid-input`, "the pages changed since").
- **Dangling references resolve as `missing`.** `apply` never refuses them. A `select` slot with several matches resolves to all of them in a stable order (runtime, then pod). The workspace shows the first and says how many matched.
- **Ids** (`PageId`, `SlotId`) follow the `Coord` id rule.
- **Serialised forms** write coordinates as strings (`toJSON`). Selectors are written as an object of strings and read back through the package's parser.
- **Sizes and exports:** no source file over 150 lines; `workspace-dock.ts` at most 226; an exported object type at most 10 members; `structure-baseline.json` may only shrink; every export goes in design.md.
- **New names, for the user's sign-off.** These are approved by the spec: Platform, UIDeployment, HostPlatform. These are listed here: `Platform.create`, `Platform.parse`, `Page`, `Slot`, `targets`, `readSelector`. Anything else is a question for the user.
- **Tests:** run `bun test --isolate` in packages/nano, packages/ui, packages/ui-workspace, packages/platform and examples. Run `bunx tsc --noEmit` at the root. Never run a bare `bun test` at the root.
- **Commits** go on `dev` and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. A contentious decision mid-build gets a full ADR (ADR-0039 onward).

## Review Focus

1. **A reload** restores the same pages, layouts and pods. No pod is made, and nothing is started for a page that isn't shown.
2. **A slot whose pod was undeployed** stays in the document and shows "not found" with a remove button. Redeploying the pod brings the slot back.
3. **A `select` slot** matching pods in two runtimes resolves to the first and reports the count. A page can hold a pod from runtime A and one from runtime B.
4. **A pod's `HostPlatform.apply`** with a stale `base` is refused. With the current base it is asked, then applied.
5. **File › Save, then Open** in a fresh browser gives the same pages. A plain `nano.json` still opens, and an old stored document migrates once.

### Task 1: The platform package

**Files:**
- Create `packages/platform/package.json` (`@pritzlaff/nano-platform`, depending on `@pritzlaff/nano-core` and `typebox`), plus `bunfig.toml` copied from packages/ui.
- Create in `packages/platform/src/`:
  - `document.ts`: types, TypeBox schema, `parse`, `readSelector`.
  - `targets.ts`: moved from `ui-workspace/src/auto-connect.ts`'s `target`.
  - `platform.ts`: `create`.
  - `host-platform.ts`: the interface.
  - `index.ts`.
- Clear the stale, untracked `packages/platform` contents first: an old `.claude/`, `node_modules/` and an empty `src/`.
- Tests: `packages/platform/test/*.test.ts`.

**Interfaces (produces):**
```ts
type UIDeployment = { pages: Record<string, Page> }
type Page = { slots: Record<string, Slot>; layout?: unknown; meta?: unknown }
type Slot = { kind: 'pod'; pod: PodCoord } | { kind: 'select'; select: SelectorData } | { kind: 'view'; view: string }
Platform.parse(json: unknown): NanoResult<UIDeployment>         // malformed → invalid-input naming page and slot
readSelector(written: Record<string, unknown>): SelectorData     // written strings → coordinates
targets(d: AppDeployment, registry: Registry): (pod: string, runtime: string) => Target | undefined
Platform.create(app: Application, registry: Registry, doc?: UIDeployment): {
  document(): { doc: UIDeployment; version: number }
  apply(next: UIDeployment, opts?: { base?: number }): NanoResult<void>   // sync; listeners called before it returns
  resolve(page: string): Record<string, Resolved>      // Resolved = { kind: 'pod', pods: PodCoord[] } | { kind: 'missing' } | { kind: 'view', view }
  open(page: string): Promise<Record<string, Opened>>  // Opened = { pod: PodCoord, started: boolean } | { fail: Fail } | Resolved (view/missing)
  listen(fn: (change: { added: string[]; removed: string[]; changed: string[]; resolved: string[] }) => void): () => void
}
HostPlatform = ns.interface('HostPlatform', { document: Op.action(Nothing, DocAt), apply: Op.action(ApplyAt, Nothing) })
// DocAt = { doc, version }, ApplyAt = { next, base }; schemas exported for the host pod
```
- `resolved` lists the pages whose resolution changed when the Application changed. The Platform listens for `app` `applied` and re-resolves.
- `open` calls `app.runtime(r).getOrCreate(p)` for the first resolved pod of each slot.

### Task 2: The workspace's Platform: boot, persistence, files, imports, HostPlatform

**Files:**
- `packages/ui-workspace/src/boot-host.ts`
- `persist.ts`
- `main.ts`
- `import-plan.ts`
- `host-deploy.ts`
- `host-pages.ts`: replaced by `host-platform-pod.ts`
- tests

**Interfaces:**
- Consumes Task 1.
- Produces the boot-time instance `platform` (the `Platform.create` result), exported from boot-host.ts in place of the `pages` store export. It is consumed by Task 3.

**Boot and persistence:**
- A new storage key holds the UIDeployment JSON, beside the app document's key.
- Saving is debounced on each Platform change.
- The another-tab check and the `pagehide` flush cover both keys.
- **Migration, run once when no UIDeployment is stored**, from:
  - the old saved-workspaces and per-dock keys;
  - a stored app document's `layout.pages`;
  - the legacy `layout[MAIN]` and top-level `slots`/`geometry`.
  
  The result is a UIDeployment: pod slots become `{ kind: 'pod' }` with `PodCoord`s, view slots become `{ kind: 'view' }`, and title, icon, order and restore point go into `meta`. Afterwards the app document is saved without `layout.pages`.

**Files and imports:**
- **File › Save** writes `{ app, platform }`.
- **Open/Import** accepts either the bundle or a plain `nano.json`. A plain one's legacy layout is migrated into the `next`.
- The Import dialog's `renameRuntimes` and `selectPods` rewrite the incoming UIDeployment's `PodCoord`s and selector `runtime` fields.
- The workspace's merge rules move from `lib/pages.ts`'s `merge` into a pure `withImported(current, incoming): UIDeployment`, which is internal. The rules: suffix clashing ids, skip identical pages, and fill a Main that shows only views. The result is applied with `platform.apply`.

**HostPlatform:**
- The host pod `platform` implements `HostPlatform`. `HOST_PODS` becomes `['ui', 'deploy', 'platform']`.
- `apply({ next, base })` is refused when stale. Otherwise it goes through the existing timed approval, whose summary names the pages and slots added or removed. It is then applied with `base`.
- `host-pages.ts` and the `pages` host pod go.

### Task 3: Nav and docks on the Platform

**Files:**
- `components/workspace-pages.ts`
- `components/nav-edit.ts`
- `dock/page-docks.ts`
- `dock/page-slots.ts`
- `dock/panels.ts`
- `components/workspace-dock.ts` (at most 226 lines)
- `lib/pages.ts`: only the workspace's rules stay; the store's write API goes
- tests

**Interfaces:**
- Consumes `platform` from Task 2.
- **The nav:** rows come from `platform.document()`, ordered by `meta.order`. `+`, rename, icon and reorder each build a `next` and call `platform.apply`. Main-first and the fixed routes are checked before applying.
- **The dock's `Storage`:** backed by its page's `layout`, written through `platform.apply` inside `quiet`. Only a page in the change report re-reconciles.
- **Panels:**
  - Each panel's state carries its slot id.
  - Each panel's pod comes from `platform.resolve`. The "first runtime placing that name" lookup goes.
  - `slotsOf` keeps each slot's kind and only adds or drops slots for panels that are opened or closed.
  - A `missing` slot shows "not found" with a remove button. Reconcile never deploys or starts it.
- **One start path:** showing a page calls `platform.open`. Panels mount with its results and retry on the Platform's `resolved` changes. `panels.ts`'s own `getOrCreate` goes.
- **A pick:** deploy a lazy pod with `addPod(h, coord, runtime)`, then `platform.apply` with a `{ kind: 'pod' }` slot.
