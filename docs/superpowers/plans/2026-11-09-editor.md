# @composable/editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The puzzle prototype rebuilt as four small rune components (component-list, type-list, type-editor, connection-board) over core, wired by subscriptions, with thin Lit elements on top and a demo page.

**Architecture:**
- **Models:** pure functions in `src/model/` (schemas and looks, the board's joining rule).
- **Components:** rune components in `src/components/`, one per concern.
- **Wiring:** `src/editor.ts` adds the four to a registry and subscribes them.
- **UI:** `src/elements/`. A small adapter, `view.ts`, puts a hidden subscriber into the same registry, so each element re-renders when its component publishes. One Lit element per component, plus `<editor-page>`.

**Tech Stack:** Bun, TypeScript, TypeBox, Lit 3, happy-dom for DOM tests, `@composable/core`, `@composable/runes`.

**Spec:** `docs/superpowers/specs/2026-11-09-editor-design.md`

## Review Focus

1. **A rename of the selected type reloads the editor.** The editor then saves to the new title, not the old one (Task 5).
2. **A brand doesn't join its base type, while an `Unknown` input joins anything.** Both cases are on the board (Task 4).
3. **Placing or moving a piece onto an occupied cell** is refused, and the state is unchanged (Task 4).
4. **Removing a component from the list** takes its pieces off the board when wired (Task 5). Otherwise the board's connections would name a component that no longer exists.
5. **An element removed from the DOM** removes its hidden view instance from the registry (Task 6).

### Task 1: Package, `model/schema.ts`, `model/looks.ts`

**Produces:**
- `type TypeEntry = { type: TSchema; look?: Look }`
- `titleOf(s): string`, where an untitled schema gives `'unknown'`
- `canonical(s): string`, JSON with sorted keys
- `sameType(a, b)`, comparing `canonical`, title included
- `takesAnything(s)`, true when the schema minus its title is `{}`
- `hashBytes(s): number[]`, 32 bytes from a small synchronous hash of `canonical`
- `builtins(): TypeEntry[]`, for `string`, `number`, `boolean` and `unknown`, each with its `title`
- `brandOf(base, title)`, a copy with the new title
- `looks.ts`, copied from `packages/puzzle-editor/src/model/looks.ts` with `lookOf(bytes: number[])` in place of `lookOf(said)` and no `EditorType`. Also `lookFor(e: TypeEntry): Look`, which is `e.look ?? lookOf(hashBytes(e.type))`.

**Tests** (`test/model.test.ts`):
- `canonical` doesn't depend on key order.
- `sameType(number, brandOf(number,'Meters'))` is false.
- `takesAnything(Type.Unknown())` is true; `takesAnything(Type.Number())` is false.
- `lookFor` is deterministic, and differs between `number` and `Meters`.
- A given look wins over the derived one.

- [ ] Write the tests and watch them fail. Implement. Run `bun test` and tsc. Commit `feat(editor): schemas and looks`.

### Task 2: `components/component-list.ts`

**Produces:** `ComponentList = component('composable.editor/component-list', …)`.
- **Getters:** `components: { id: string; ops: Op[] }[]` and `selected: { component?: string; op?: string }`.
- **Actions:**
  - `set(list)`;
  - `add({ id, ops })`, refused when the id already exists;
  - `remove(id)`;
  - `addOp({ component, op })` and `removeOp({ component, op: key })`;
  - `select({ component, op? })`.
- **Events:** `componentSelected(id)`, `opSelected({ component, op: key })` and `removed(id)`.

Refusals throw, so the call returns `{ error }`.

- [ ] Write tests for every action and event, plus "add a duplicate id is refused" and "removeOp of an unknown op is refused". Watch them fail. Implement. Commit `feat(editor): component list`.

### Task 3: `components/type-list.ts` and `components/type-editor.ts`

**TypeList** (`composable.editor/type-list`):
- **Getters:** `types: TypeEntry[]`, where the built-ins are always first, and `selected?: string`, a title.
- **Actions:**
  - `set(entries)`, which keeps the built-ins;
  - `add(title)`, which adds an empty `Type.Object({}, { title })`;
  - `rename({ from, to })`, refused for built-ins and for existing names. If `from` was selected, it re-emits `typeSelected`.
  - `copyAsBrand({ from, to })`;
  - `remove(title)`, refused for built-ins;
  - `select(title)`, which emits `typeSelected(entry)`;
  - `update(entry)`, which replaces by `entry.type.title` and refuses an unknown title.

**TypeEditor** (`composable.editor/type-editor`):
- **Getter:** `entry?: TypeEntry`.
- **Actions:**
  - `edit(entry)`;
  - `addField({ name, type: TSchema })`, refused on a non-object type or a duplicate name;
  - `removeField(name)`;
  - `setField({ name, type })`;
  - `setLook(look)` and `resetLook()`.
- **Event:** every change emits `typeChanged(entry)`.

- [ ] Write tests for each action. Watch them fail. Implement. Commit `feat(editor): type list and type editor`.

### Task 4: `model/board.ts` and `components/connection-board.ts`

**Model:**
- `type Piece = { instance: string; op: Op; cell: { c: number; r: number } }`
- `joins(left: Op, right: Op): boolean`. The left piece needs an output and the right piece an input; they join when `sameType(left.output, right.input)` or `takesAnything(right.input)`.
- `connectionsOf(pieces): Omit<Subscription,'id'>[]`, made from each neighbouring pair (`c + 1`, same `r`) that joins.

**ConnectionBoard** (`composable.editor/connection-board`):
- **Getters:** `pieces` and `connections`, which is derived.
- **Actions:**
  - `set(pieces)`;
  - `place({ instance, op, cell })` and `move({ from: cell, to: cell })`, both refused on an occupied cell;
  - `takeOff(cell)`;
  - `removeInstance(id)`, which takes off every piece of that instance.

**Tests:**
- slider → doubler → chart gives 2 connections with the exact `{ source, op, listener, target }`.
- A `Meters` sink after a number source gives no connection.
- An `Unknown` sink joins anything.
- A gap breaks the chain.
- Placing onto an occupied cell is refused, and `pieces` is unchanged. Moving onto one is refused the same way.
- The same instance can be placed twice.

- [ ] Write the tests. Watch them fail. Implement. Commit `feat(editor): connection board`.

### Task 5: `editor.ts`, the wiring

**Produces:**
- `addEditor(registry: Registry, prefix = 'editor'): Ids`. It adds four instances under `${prefix}-list`, `-types`, `-type-editor` and `-board`, and subscribes them:
  - `types/typeSelected → type-editor/edit`
  - `type-editor/typeChanged → types/update`
  - `list/removed → board/removeInstance`
- `Ids` gives those four instance ids.

**Tests:**
- Selecting a type loads it into the editor.
- Adding a field updates the list's entry.
- Renaming the selected type and then adding a field updates the new title, and no entry with the old title comes back (Review Focus 1).
- Removing a component from the list takes its pieces off the board (Review Focus 4).

- [ ] Write the tests. Watch them fail. Implement. Commit `feat(editor): compose the editor by subscriptions`.

### Task 6: `elements/view.ts`, the adapter

**Produces:** `abstract class ModelElement extends LitElement`.
- **Properties:** `registry: Registry` and `model: string`, the instance id.
- **On connect:**
  - It adds a hidden view instance, `${model}~view-${n}`, whose only action is `changed`.
  - It subscribes `changed` to every source op of the model, and calls `requestUpdate()` when one arrives.
- **On disconnect:** it removes that instance (Review Focus 5).
- **Reading and acting:**
  - `read<T>(op)` returns the model's current value of the source op, cached from the last publish or read on connect.
  - `act(op, arg)` calls the model through the view's handle and returns the `Result`. The latest error stays in `this.problem` for rendering.

**Tests** (`test/view.test.ts`, happy-dom):
- A test element re-renders after the model changes.
- `act` returns the error from a refused action.
- Removing the element removes the view instance from the registry snapshot.

- [ ] Write the tests. Watch them fail. Implement. Commit `feat(editor): model element adapter`.

### Task 7: Elements, page and demo

**Produces** in `elements/`:
- `<component-list-el>`: components with their ops, a `+ Element` form, and per-op add and remove.
- `<type-list-el>`: types, with `+ New record type`, rename, `Copy as brand` and delete.
- `<type-editor-el>`: the fields, each with a type picker; preset and swatch pickers for the look; and `Regenerate from SHA`, which is `resetLook`.
- `<connection-board-el>`: a grid of pieces drawn with their type looks. Click a component op in the list, then a cell, to place it. Selecting a piece shows `Take off`.
- `<editor-page>`: a tab bar (Elements and Types) over the list and type panes, with the board alongside.
- `defineElements()` defines them all.

`demo/index.html` plus `demo/main.ts`:
- **Setup:** a runtime and registry, `addEditor`, and the four demo components (slider, doubler, chart, meter) seeded into the list as spec'd.
- **Page:** `<editor-page>`.

**Tests** (`test/elements.test.ts`, happy-dom):
- The page renders all four panes.
- Clicking `+ New record type`, typing a name and Create adds the type to the list.
- Placing slider then doubler on neighbouring cells shows 1 connection in the board's connection list.

- [ ] Write the tests. Watch them fail. Implement. Commit `feat(editor): elements, page and demo`.
