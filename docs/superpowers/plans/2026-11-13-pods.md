# Pods Revision Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the 36 `test.todo` behaviours in `packages/nano/test/pods.test.ts` green: pods own their instances
(count, deterministic `<pod>#<n>` coordinates, swap in place, per-instance failure), subscriptions are explicit
one-to-one edges chosen with mandatory end selectors, deleting cascades while unavailable ends wait, and the
application starts runtimes instead of opening them.

**Architecture:** A runtime holds **pod records** shared by reference with every runtime the pod is placed into, so a
swap or a failure is seen everywhere without propagation code (`rehome` and the replace fan-out go). Each pod record
holds its instances (each a host pod from `pod.ts`, renamed `instance` internally) with a state. Subscriptions keep
today's concrete shape; `connect` resolves selectors to coords and then subscribes. The document saves pods
(implementation, config, instance indices, next index) instead of instances.

**Tech Stack:** Bun 1.3, TypeScript, TypeBox 1.x; no new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-13-runtime-model-design.md` (the revised sections: domains table, "Coordinates,
precisely", "Subscriptions become connections", "Connecting: selectors choose the two ends, once", "Failure
boundaries", "Behaviours (written as tests first)", "The Application"). The tests: `packages/nano/test/pods.test.ts`
(and its API notes in `.superpowers/sdd/2026-11-13-runtime-model/pods-tests-report.md`). Read both.

## Global Constraints

- Tests: `cd packages/nano && bun test --isolate`; `cd examples && bun test --isolate`; types `bunx tsc --noEmit` at
  the root. Every test file runs in well under a second.
- Commit to the checked-out branch `dev-examples` (never switch), one commit per task, each ending
  `Co-Authored-By: <the model that wrote it> <noreply@anthropic.com>`. Never commit `kerits/`, `designs/`, `spikes/`.
- Each task flips its `test.todo`s in `pods.test.ts` to `test` and keeps them unchanged otherwise; a test that must
  change is a decision-log entry. The `// @ts-nocheck` line goes when the last todo flips (Task 5).
- Existing tests that use replaced API (instance coords `<impl>#<id>`, `replace`, `rehome`, `open`, members-as-instances)
  are migrated in the task that changes that API, keeping the behaviour they pin unless the spec changed it.
- Platform failures are `NanoResult` fails, never thrown across the runtime (bare factories with a bad id excepted,
  decision 41).
- Decisions met while building go in `docs/decisions.md` (append-only; an entry the revision overturns gets a
  "Superseded by N" line). Every module keeps its responsibility comment and example.
- Instance coordinate: `` `${podId}#${n}` ``; pod ids follow the existing id rule (decision 41); indices start at 0 and
  are never reused within a pod.
- Pod state: `starting` if any instance is starting; else `failed` if any instance failed; else `stopped` if every
  instance is stopped; else `running`.

## Review Focus

1. **A swap while calls are in flight:** calls already inside the old instance finish with its result; calls after
   the swap reach the new one; the old instance is disposed once its in-flight calls settle. *(Task 4 test.)*
2. **Removing a pod placed into other runtimes:** its subscriptions are deleted in every runtime that holds it, and
   it leaves each runtime's membership. *(Task 4 test.)*
3. **Connecting in a guest runtime:** `{ implements }` and `{ implementation }` targets consider pods placed into the
   runtime as well as its own, and still fail `<n> match` when both fit. *(Task 3 test.)*
4. **Indices survive a save:** remove `log#0`, save, load, add an instance → `log#1`, never `log#0`. *(Task 5 test.)*
5. **Provisioning onto a failed instance:** a dependency whose only match is a failed instance is subscribed to and
   waits (the role counts as satisfied only once live). *(Task 1 test.)*

### Task 6: One observable stream per runtime

Today observability is split: `rt.listen` carries lifecycle and wiring events, while messages and exceptions go to a
`pod.observe` callback fixed at construction; denied messages are only counted, and warnings are a pull-only
`app.notes()`. This task makes `rt.listen` the single stream a person (or a test, or the host) watches.

**Files:**
- Create: `packages/nano/src/runtime/trace.ts` (the event type and a safe emitter)
- Modify: `packages/nano/src/runtime/index.ts`, `runtime/calls.ts`, `runtime/pods.ts`, `src/application.ts`
- Test: `packages/nano/test/trace.test.ts`; migrate tests using `opts.pod.observe` to `listen`

**Interfaces:**
- Produces: `type RuntimeEvent` (replacing today's) =
  - lifecycle: `{ type: 'pod-created'; pod; implementation }`, `{ type: 'pod-removed'; pod }`,
    `{ type: 'pod-swapped'; pod; from: string; to: string }`, `{ type: 'instance'; coord; state: InstanceState; reason?: string }`
    (every state change: starting, running, failed with reason, stopped, and removal as `stopped` then gone);
  - wiring: `{ type: 'subscription-set'; subscription }`, `{ type: 'subscription-removed'; id; reason: 'unsubscribed' | 'cascade' }`,
    `{ type: 'status'; id; status }`;
  - messages: `{ type: 'sent'; id: string /* message id */; subscription?: string; from; to; port; kind: 'call' | 'event' }`, then exactly one of
    `{ type: 'delivered'; id; result: NanoResult<unknown>; ms: number }` or `{ type: 'denied'; id; reason }`;
    a publish emits `sent`/`delivered` per delivery;
  - problems: `{ type: 'failure'; coord?; reason }` (a handler threw or timed out, a policy threw, a bad publish) and
    `{ type: 'warning'; reason }` (the application's notes, as they happen).
  - `Runtime.listen(fn: (e: RuntimeEvent) => void): () => void` — every event above, in order; a throwing listener is
    swallowed. The `pod.observe` construction option goes. `app.notes()` stays as a log of the warnings.

- [ ] **Step 1: Write failing tests** in `trace.test.ts`, one behaviour each:
  - "creating a pod emits pod-created, then an instance starting and running for each instance";
  - "a make that throws emits the instance failed, with the reason";
  - "a call emits sent then delivered, with the subscription, the result and its duration";
  - "a denied call emits sent then denied, and is not counted";
  - "a publish emits sent and delivered for each delivery";
  - "a handler that throws emits a failure for its instance";
  - "removing a pod emits subscription-removed with reason cascade for each of its subscriptions, then pod-removed";
  - "a skipped member while starting emits a warning (and app.notes() lists it)";
  - "a listener that throws never breaks the runtime".
- [ ] **Step 2: Run.** Expect FAIL.
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run** all + tsc. Expect PASS.
- [ ] **Step 5: Commit** `feat(nano): one observable stream per runtime — lifecycle, wiring, messages, failures, warnings`
