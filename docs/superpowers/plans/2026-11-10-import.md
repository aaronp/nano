# Import components from a URL — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Paste a manifest URL in the drawer's Import dialog; the package's components join the host (platform catalog, docks, drawers), are remembered, and reload at start-up.

**Architecture:** One `bun build` with code splitting emits `main.js` and `shared/<name>.js` entries (one per shared specifier), sharing chunks; `index.html`'s import map points bare specifiers at them. Pure helpers in `src/lib/imports.ts` (manifest check, range matching, clashes, catalog check, store). `composable.ts` exposes `addCatalog`; the dock gains `addTemplate`; drawers render an Imported section on `catalog:changed`. `src/components/import-dialog.ts` and `src/imports.ts` (load a package; start-up loading) do the rest.

**Spec:** `docs/superpowers/specs/2026-11-10-import-design.md`

## Global Constraints
- Shared specifiers (exactly): `@pritzlaff/nano-core`, `@pritzlaff/nano-runes`, `@pritzlaff/nano-elements`, `lit`, `lit/decorators.js`, `lit/directive.js`, `lit/directives/class-map.js`, `lit/directives/style-map.js`, `lit/directives/repeat.js`, `lit/directives/if-defined.js`, `typebox`, `typebox/value`.
- Manifest version 1 as `templates/nano-template/src/manifest.ts` writes it.
- Imports kept in localStorage under `workspace-starter.imports` as `{ url, name, version }[]`.
- Nothing imports `workspace-dock.ts` in tests (golden-layout can't load under bun); tests import the DOM before lit (dynamic imports after `GlobalRegistrator.register()`).
- Files ≤ ~200 lines; commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus
1. **One copy of each shared library** in the page: main.js and the shared entries share chunks; no shared library is bundled twice (Task 1).
2. **A refused import adds nothing** (bad manifest, clash, load failure, catalog/manifest mismatch) (Tasks 2, 4).
3. **Start-up with a failing remembered import still boots,** and the failure shows in the drawer (Task 4).
4. **A package imported after docks exist** shows in every drawer and can be added to every dock (Task 3).
5. **Range checks:** `^0.1.0` accepts 0.1.5 and refuses 0.2.0; `^1.4.0` accepts 1.9.0, refuses 2.0.0; `~`, exact, and `*` behave (Task 2).

### Task 1: Shared libraries and the import map
- `src/shared/<name>.ts`, one per shared specifier: `export * from '<specifier>'` (names: `nano-core`, `nano-runes`, `nano-elements`, `lit`, `lit-decorators`, `lit-directive`, `lit-class-map`, `lit-style-map`, `lit-repeat`, `lit-if-defined`, `typebox`, `typebox-value`); `src/shared/specifiers.ts` exports the list `{ specifier, file }[]`.
- `scripts/versions.ts` (in ui-workspace): writes `public/shared/versions.json` `{ specifier: version }` for the five packages (from their package.json).
- `package.json` scripts: `build` = `bun scripts/versions.ts && bun build src/main.ts src/shared/*.ts --outdir public --root src --splitting --format esm --minify --sourcemap=linked --loader .css:text`; `dev` likewise with `--watch` (no minify).
- `public/index.html`: `<script type="importmap">` mapping each specifier to `./shared/<file>.js`, before the module script.
- Test `test/shared.test.ts`: the import map lists exactly the specifiers in `specifiers.ts`, each to an existing `public/shared/*.js` after a build (run the build in the test); `versions.json` has the five packages; `main.js` contains no second copy: `grep` the emitted files for lit's `class ReactiveElement` definition — it appears in exactly one file.
- [ ] RED, GREEN, commit `build(ui-workspace): shared libraries as split modules, with an import map`.

### Task 2: The pure parts — `src/lib/imports.ts`
- `parseManifest(json: unknown): Manifest | string` (refusal sentence); `satisfies(version, range): boolean` (`^`, `~`, exact, `*`, `>=`); `sharedReport(manifest, provided: Record<string,string>): { specifier, range, provided?, ok }[]`; `clashes(manifest, loaded: { kinds: string[]; ids: string[]; tags: string[] }): string[]`; `catalogMismatch(manifest, catalog): string | null`; `importsStore(storage)` with `list()`, `put({url,name,version})` (replaces by url), `remove(url)`.
- Tests `test/imports.test.ts`: Review Focus 5's ranges; a template-built manifest parses; missing fields and `manifest: 2` refused; clashes on kind, id and tag listed; mismatch found when the catalog lacks a kind or a tag differs; store put/replace/remove.
- [ ] RED, GREEN, commit `feat(ui-workspace): manifest, ranges, clashes and the imports store`.

### Task 3: Adding a catalog to a running host
- `composable.ts`: `addCatalog(entries: Catalog, from: { name: string; url: string })`: merges into the exported `catalog` object (which the platform holds), adds a `template[data-widget][data-title][data-catalog][data-package=name]` per tagged entry to every `workspace-dock` (via its `addTemplate` when defined, else appended to the dock element so it is read at connect), records `loaded` kinds/ids/tags, and dispatches `catalog:changed` on `document`. `loadedNames()` for clash checks.
- `workspace-dock.ts`: `addTemplate(t)` appends it and registers it in `defs`.
- `component-drawer.ts`: on `catalog:changed` (and at build), (re)renders an **Imported** section: per package (from templates' `data-package`) a heading with ✕ (`aria-label="Remove <name>"`, dispatches `imports:remove` with the url) and its entries (registered with the dock); a failed start-up import shows as a line with its error (from a `imports:failed` detail list on `document`).
- Tests: `test/host.test.ts`: after `addCatalog({ timer: … }, …)` the platform's `create-component` can make a `timer`, Main's dock has its template; `test/drawer.test.ts`: `catalog:changed` makes an Imported section with the package heading and entries, each handed to `addSource`; ✕ dispatches `imports:remove`.
- [ ] RED, GREEN, commit `feat(ui-workspace): add a package's catalog to a running host`.

### Task 4: Loading, the dialog, start-up
- `src/imports.ts`: `loadPackage(url): Promise<{ manifest, catalog } | { error }>` — fetch, `parseManifest`, `clashes`, `import(new URL(manifest.module, url))`, check `catalog`/`define` exports, `catalogMismatch`, then `define()` and `addCatalog`. `bootImports()`: for each remembered import, `loadPackage`, collecting failures into `imports:failed`; awaited from `boot-saved-workspaces.ts` (before docks are defined). `imports:remove` handler: `importsStore.remove`.
- `src/components/import-dialog.ts`: the drawer's Import button (enabled) opens it: URL → Fetch → preview (package, version, module URL, components with ops, shared report with ✓/⚠) → Import (disabled with reason on refusal) → on success `importsStore.put`, close; a re-import of a known url notes "a newer version takes effect after a reload".
- Tests `test/import.test.ts` with a `Bun.serve` fixture (a manifest and a module using `@pritzlaff/nano-runes`, served with CORS): loading adds its kind to the catalog and defines its tag; a clash, a bad manifest, a 404 module and a catalog mismatch each return `{ error }` and add nothing; `bootImports` with one good and one dead url loads the good one and reports the dead one; the dialog drives fetch → preview → import.
- [ ] RED, GREEN, commit `feat(ui-workspace): import a package from its manifest URL; remembered imports load at start-up`.

- [ ] Commit `docs(template): what a package may import; its preview server allows cross-origin imports`.
